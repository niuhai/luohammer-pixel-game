## Outcome Contract

- 场景：首次开始游戏后，序章预热 `GameScene` 代码块失败，或 GameScene 首章三张
  图片在 Phaser 重试后仍加载失败。
- 用户：电脑端为主、手机端为护栏；Chromium 开发构建，路由层真实注入 HTTP 503，
  Service Worker 关闭以排除缓存掩盖。
- 创作意图：网络失败不应该把玩家丢回一个需要猜测下一步的黑箱；代码不可用时要
  给出明确恢复选择，可降级图片不可用时则应诚实说明但不阻断人生选择。
- 可观察问题：
  - `GameScene` 代码 503 后，错误卡只有 1.6 秒、`pointer-events:none`，无按钮；
    焦点已经落在全屏层背后的“开始游戏”。卡片文案称“已返回标题页”，视觉上却
    仍覆盖标题，2.1 秒后直接消失。
  - 三张首章图片全部 503 时，Phaser 会继续并由 PixelRenderer 使用 Graphics
    兜底，但天赋页没有任何降级说明；探针确认 `bg-classroom`、`char-standing`、
    `char-young` 三个纹理均不存在。
- 用户结果假设：在动态场景代码或首章资源真实失败时，保留明确失败原因、无损返回说明和可聚焦重试动作，并区分可降级纹理与必须重试的代码失败，可以让玩家从网络异常中自行恢复，而不是只看到短暂提示后猜测下一步。
- 变化契约：从“短暂不可操作错误 / 静默降级”变为“代码失败提供持续的重新加载与
  返回标题选择；图片失败带说明继续使用简化舞台”。
- 重点品质维度：错误恢复、反馈与状态、键盘焦点、跨端适应性。
- 不改变：序章时间线与 `UI-FREEZE-INTRO`、Phaser 20 秒 / 2 次重试策略、
  PixelRenderer Graphics 兜底、天赋翻牌与故事数据。
- 主验收：Chromium 1440×900。
- 扩展验收：桌面 1366×768、1920×1080；手机 390×844、375×812、360×800。
- 验收标准：
  - 代码失败态为 `alertdialog` / `aria-modal=true`，持续保留，主动作 ≥44px 且
    自动获得焦点；
  - Enter 激活“重新加载游戏”后发生真实 navigation，并回到加载层已清理的标题页；
  - “先回标题”允许放弃重试并恢复标题主操作焦点；
  - 图片失败仍进入天赋页，出现不阻断的 `role=status` 简化舞台说明，桌面/手机
    均不越界。
- 最低自动化验证：L3。
- 回退：核心路径、可读性、焦点或移动端任一退化即回退本轮改动。

## 实现

- `GameLoadingUI` 的 error 阶段从自动消失状态升级为可选的持续恢复对话框：
  `alertdialog`、重新加载/先回标题双动作、明确焦点、44px 触控高度，并在桌面横排、
  手机竖排。无恢复动作的旧调用仍保留自动清理兼容。
- `BootScene` 接收 `gameplayLoadFailed` 场景数据，在标题 DOM 完成接管后显示恢复
  对话框；“重新加载”使用完整 page reload，避免 ESM module graph 缓存同 URL
  的失败状态，“先回标题”淡出错误层并把焦点交还标题主操作。
- `IntroScene` 三条代码加载失败分支统一传递恢复状态，不再各自短暂显示错误后静默
  返回；不改动成功时序。
- `GameScene` 记录 preload 的最终 `loaderror` key；只要存在失败纹理，就通过全局
  Toast 显示“已启用简化舞台，不影响选择与游戏进度”，同时继续既有 Graphics
  兜底，不增加阻断步骤。
- Toast 增加 `data-toast-type`、`role=status|alert`、live politeness 与 atomic
  语义，使降级状态既可自动化识别也可被读屏器感知。
- 新增真实 503 失败探针：六视口代码块失败、键盘 reload、标题恢复，以及桌面/
  手机三图失败和 warning 边界。

## Outcome Contract

- 场景：随机事件在主线节点间插入；部分剧情选项随后执行确定性属性检定。
- 用户：电脑端为主、手机端为护栏；需要在高压叙事中快速理解选项影响，并用键盘、
  触控或读屏完成结果确认。
- 可观察问题：
  - 基线六视口的随机事件选项只有行动文案，影响预览数量均为 0；玩家只能盲选，
    事件级 `effectVariance` 还未进入实际结算；
  - 随机事件结果只显示脱离上下文的属性数字，使用 `status/assertive` 自动消失，
    没有所选行动、继续按钮或结果焦点；
  - 属性检定是确定性阈值，但选项提示用原始属性伪造 10%–90%“成功率”，忽略
    一呼百应、人脉编织者和成就猎人加成；
  - 检定结果层没有 dialog 语义、焦点、基础值/加成拆分、剧情后果或结果属性，
    并在约 1.8 秒后自动消失。
- 用户结果假设：把随机事件、属性检定条件、风险收益和结算结果组织成连续且可聚焦的决策层级，可以让玩家在高压剧情节点快速理解为什么触发、选项会影响什么以及结果如何落地，同时避免手机端误选或信息被遮挡。
- 变化契约：从“盲选—数字闪现—检定概率错觉”变为“方向预览—选择落地—确定性
  门槛核对—后果确认”的连续决策链。
- 重点品质维度：决策信息层级、规则可信度、结果可读性、焦点交接和跨端容量。
- 不改变：随机事件触发条件、主线节点、属性阈值、天赋加成规则、序章冻结时间线。
- 主验收：Chromium 1440×900。
- 扩展验收：桌面 1366×768、1920×1080；手机 390×844、375×812、360×800。
- 验收标准：
  - 每个随机事件选项显示方向级影响预览和波动提示，读屏名称包含同等信息；
  - 结果保留事件、所选行动与实际数值，使用可聚焦 dialog 和 ≥44px 明确继续动作；
  - 选项检定提示显示实际总值、门槛、差距和加成；读心术揭示真实成功/失败路径，
    不再展示虚构概率；
  - 检定结果展示基础值 + 加成 = 检定值 / 门槛、剧情后果与最终属性，并等待确认；
  - 六视口卡片不越界，方向键、数字键、Enter、Escape 和触控尺寸均通过。
- 最低自动化验证：L3。
- 回退：核心路径、可读性、焦点或移动端任一退化即回退本轮改动。

## 实现

- 新增 `DecisionPresentation` 共享层，统一属性标签、收益/代价色彩、方向摘要、
  HTML 转义与三类检定加成快照；ChoiceSystem 和 GameScene 共用同一计算。
- 随机事件选项新增方向级影响 token、波动提示和包含影响的读屏名称；补齐方向键
  循环，事件级波动在选择未单独声明时进入实际结算。
- 随机事件结果重做为显式确认 dialog：保留事件标题、所选行动、实际属性和 48px
  继续动作；焦点同步进入结果层，Tab 收束，Escape/按钮只推进一次，不再自动消失。
- 属性检定提示改为“当前值 / 门槛 / 差距”，读心术显示成功与失败的真实结果方向；
  同步更新技能说明，移除误导性的概率措辞。
- 检定结果层增加基础值、加成、总值、门槛、剧情后果和最终属性；结果等待用户确认，
  支持焦点收束、Escape、减少动态效果和短屏内部滚动。
- 失败减免先解析为最终效果，再同时用于结果呈现和实际应用，避免 UI 说一套、
  结算落地另一套。
- HEAD 在本轮中由 `9dab16c` 外部推进到 `6e214b7`（R025 提交）；已检查并保留，
  未重置用户工作。该提交带回的 Toast 三条并显旧测试被校准到已提交的单活动契约，
  未改变通知系统运行行为。

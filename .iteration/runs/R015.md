# R015 · 阶段结算的阅读控制与可访问焦点

- 日期：2026-07-29
- 状态：CLOSED

- 周期：2026-07-28-v4.2-first
- 起点：2bb38a3

## Outcome Contract

- 可观察问题：阶段结算是全屏阻断层，却没有 dialog/aria-modal 语义，也不会把焦点移入“继续”按钮；用户已经按下指针开始阅读后，5 秒自动继续仍会照常倒数。
- 用户结果假设：把阶段结算声明为可控对话框、聚焦继续操作，并在用户交互后暂停自动倒计时，可以让键盘和读屏用户完整阅读阶段结果而不被自动跳过。
- 主验收：Chromium 1440×900。
- 移动护栏：Chromium 390×844、375×812。
- 最低自动化验证：L3。
- 回退：核心路径、可读性、焦点或移动端任一退化即回退本轮改动。

## 所需证据

- [x] settlement_dialog_semantics
- [x] countdown_pause_on_interaction
- [x] desktop_mobile_readability

## 实现

- 为结算层补充 `role="dialog"`、`aria-modal`、标题和正文关联，并为继续按钮设置明确可访问名称。
- 弹层出现后自动聚焦“继续”；Tab/Shift+Tab 保持在唯一主操作上，Enter 可完成结算。
- 指针按下、触摸、滚轮或键盘操作都会暂停自动继续，并把提示更新为“自动继续已暂停 · 阅读完后请按继续”。
- 取消点击遮罩直接跳过，避免玩家为了滚动或恢复焦点而误关结算。
- 将卡片改为“正文独立滚动 + 底部操作常驻”，手机端长内容也不会把继续按钮挤出视口。
- 提高暂停说明的最小字号，并补充可见键盘焦点环。

## 验证

- 基线 1440×900：无 dialog 语义、继续按钮未获焦，指针操作 1 秒后倒计时从 5 秒降到 4 秒。
- 改后 1440×900：dialog 语义与标题/正文关联完整，继续按钮初始聚焦；指针操作后倒计时停止并显示暂停说明。
- 改后 390×844：卡片四边均在视口内；Tab 后仍聚焦继续按钮并暂停倒计时，Enter 仅执行一次完成回调。
- 首次 L3 暴露结算焦点样式缺少右花括号，导致后续启动页 CSS 未解析；修复后从头重跑，不沿用部分结果。

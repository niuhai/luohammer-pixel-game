## Outcome Contract

- 可观察问题：
  - 使用 3 / 35 已解锁结局的确定性探针观察时，弹窗内 35 张卡片均为普通
    `div`，唯一可聚焦元素是关闭按钮；玩家无法用键盘进入或浏览已解锁结局。
  - “数码博主”完整正文为 112 字，静态卡片只保留 81 字，且不存在展开入口。
  - 收集进度条与结局网格没有 `progressbar` / `list` 语义，锁定项也没有可供
    读屏理解的状态与提示。
  - 基线弹窗在 1440×900、390×844、375×812 均未横向越界，因此本轮必须
    在增加详情后继续守住三档容量。
- 用户结果假设：把已解锁结局从静态截断卡片升级为可聚焦、可展开的完整详情，并为收集进度和锁定提示补充准确语义，可以让玩家真正回顾已达成结局，而不只是看到一个无法操作的缩略清单。
- 不改变：
  - 结局判定、解锁存储与标题页/结局页的调用入口；
  - 既有暗色像素金色视觉语言；
  - `UI-FREEZE-INTRO` 序章冻结区。
- 主验收：Chromium 1440×900。
- 移动护栏：Chromium 390×844、375×812。
- 最低自动化验证：L3。
- 回退：核心路径、可读性、焦点或移动端任一退化即回退本轮改动。

## 实现

- 已解锁卡片改为原生按钮摘要，提供 `aria-expanded` / `aria-controls` 与明确的
  “查看完整结局”入口；弹窗打开后优先聚焦第一个已解锁结局。
- 新增共享详情区，展示完整正文与此前图鉴未展示的“值得尊重”内容；再次激活、
  收起按钮或第一次 Escape 可收起详情，第二次 Escape 关闭弹窗并归还焦点。
- 方向键在已解锁结局间前后浏览，Home / End 可跳到首尾；Tab 继续沿用弹窗
  焦点陷阱。
- 进度条补充精确数值语义，网格与卡片补充 list / listitem 语义，锁定卡片提供
  不泄露结局名的读屏提示。
- 详情区、按钮焦点态与 44px 收起操作复用现有视觉语言；390 / 375 窄屏使用
  双列网格和受控详情高度；减少动态效果下关闭入场与进度动画。
- 新增：
  - `test/unit/ending-gallery.test.js`
  - `test/e2e/ending-gallery-detail.spec.js`

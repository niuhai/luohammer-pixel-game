# R013 · 新游戏防误触与存档安全交接

- 日期：2026-07-28

## Outcome Contract

- 可观察问题：返回玩家标题页的“新游戏”会在第一次点击时立即删除 `luohammer_save` 与 `luohammer_save_backup` 并进入序章；没有确认状态，也无法用 Escape、失焦或超时撤销。
- 用户结果假设：把会清除自动存档的新游戏操作改为轻量二次确认，并在确认前保持存档不变，可以降低返回玩家误触丢进度的风险而不引入重型弹窗。
- 主验收：Chromium 1440×900。
- 移动护栏：Chromium 390×844、375×812。
- 最低自动化验证：L3。
- 回退：核心路径、可读性、焦点或移动端任一退化即回退本轮改动。

## 所需证据

- [x] new_game_first_click_guard
- [x] save_preserved_before_confirmation
- [x] keyboard_cancel_and_timeout

## 实现

- 将“新游戏”改为按钮内轻量二次确认：首次点击切换为“确认重新开始”，再次点击才清除当前自动存档并进入序章。
- 确认态使用明确红色背景、边框和光晕，并通过 `aria-label` / `title` 说明自动存档会清除、手动存档不受影响。
- 首次点击显示 3 秒非阻塞提示，避免另开全屏确认弹窗。
- 支持 Escape、焦点移出和 3.2 秒超时三种取消方式，取消后恢复“新游戏”文案和语义。
- 新增 `test/e2e/new-game-guard.spec.js`，自动验证首次点击存档不变、三种取消路径、最终二次确认清档与进入序章。

## 验证

- 优化前：首次点击即离开标题页，自动存档与备份同时消失。
- 优化后：首次点击仍停留标题页，自动存档与备份均保留，按钮进入 `data-confirming="true"` 状态。
- Escape、失焦、3.2 秒超时均会复位，且复位后存档仍存在。
- 只有第二次点击确认后才进入序章并清除自动存档；手动槽位未参与 `SaveSystem.clear()`。
- L3：ESLint 通过；21 个测试文件 / 359 条单元测试通过；生产构建通过；23 条 Chromium E2E 旅程通过。

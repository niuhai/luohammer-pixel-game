# 《罗的十字路口》决赛优化验收标准 v1

> 目标：把“还能优化”变成可验证的门槛。每轮只接受能提高评委得分、玩家体验或提交可信度的改动。
>
> 评分依据：产品完整性 30% / 技术实现 30% / 实用性 20% / 创新性 20%。

## 一、总放行标准

进入发布冻结期前必须同时满足：

1. 加权复赛就绪度不低于 **9.2/10**，四个维度均不低于 **8.8**。
2. 连续两轮扫描 **P0=0**，剩余 P1 不超过 2 个且均为高成本、低收益项。
3. lint、unit、build、剧情校验、路径模拟、effects 校验、E2E 全部通过。
4. 标题页→天赋→关键选择→6 亿杀手时刻→结局→分享卡完整路径无阻断。
5. 375×812、768×1024、1920×1080 三档视口均完成截图验收。
6. 复赛帖中的数字、功能、截图和体验地址与当前部署版本完全一致。
7. 3 分钟演示视频已录制并在无开发环境的设备上完整播放。

任何一项不满足，项目都只能标记为“可演示”，不能标记为“决赛就绪”。

## 二、七个体验维度的量化门槛

| 维度 | 决赛门槛 | 证据 |
|---|---|---|
| 前端交互 | 首屏 3 秒内出现可理解反馈；点击后 100ms 内出现视觉或声音响应；所有选择防连点；键盘与触屏均可完成主路径 | 录屏计时、Playwright、控制台日志 |
| UI 样式 | 正文最小 14px；主操作热区不小于 44×44px；三档视口无裁切/遮挡；键盘焦点可见；关键文字对比度达到 WCAG AA | 三档截图、人工检查 |
| 声音 | 标题、六阶段、结局的音乐情绪可辨；关键点击/选择/成就/崩溃均有反馈；静音和音量跨会话保存；TTS 不阻塞剧情且失败可降级 | 实机录音、状态恢复测试 |
| 可玩性 | 前 30 秒完成第一次有效选择；3 分钟内出现一次明显代价；关键检定成功/失败体感不同；至少 5 类结局可由模拟策略稳定触发；第二周目有明确新增目标 | 路径模拟、玩家走查记录 |
| 交互逻辑 | 存档损坏有明确提示；旧存档可迁移或安全拒绝；场景退出后无残留 DOM/定时器；结局判定稳定；剧情零死链零卡死 | unit/E2E、validate-story、内存走查 |
| 图片生动性 | 每个生命阶段至少有独立色调；关键节点有角色微动效或场景特效；35 个结局至少按情绪分组形成可辨识的视觉差异 | 关键帧截图、结局矩阵 |
| 文本完整度 | 每章至少 3 句截图级金句；选择项同时表达收益与代价；historyNote 提供“为何重要”的信息增量；结局文案不重复；无事实与代码数字冲突 | 文本扫描、人工抽检、相似度报告 |

## 三、四个评委评分维度

### 产品完整性（目标 ≥9.2）

- 新玩家无需说明即可开始、继续、存档、静音并抵达结局。
- 所有界面声明的功能都有真实运行逻辑；规划中功能必须明确标注为规划中。
- 错误态、空态、加载态和恢复路径均有玩家可见反馈。

### 技术实现（目标 ≥9.0）

- 自动化验证全绿，控制台无 error，生产构建无阻断警告。
- DOM 与 Phaser 场景生命周期同步，不遗留 overlay、监听器或定时器。
- 新机制必须有直接覆盖其业务承诺的测试，不能只靠字符串白名单证明“已实现”。

### 实用性（目标 ≥8.8）

- 单局 10–15 分钟能形成完整情绪曲线。
- 第二周目能通过新结局、成就、随机事件和永久技能获得实质差异。
- 结局复盘能帮助玩家理解自己的选择倾向，而不只是展示分数。

### 创新性（目标 ≥9.3）

- “6 亿数字砸出”是明确的记忆锚点，演示视频必须完整呈现。
- AI 人生复盘在有 Key 时实时生成、无 Key 时可靠降级，并清楚标注来源。
- Loop Engineering 的轮次、修复数和验证证据可核验，不能只作为宣传口号。

## 四、单项改动准入规则

每个优化任务必须写清：

- 对应评委维度和预计提分；
- 当前问题的文件、节点或截图证据；
- 玩家可感知的前后差异；
- 自动化验收与人工验收方式；
- 可能破坏的路径；
- 完成后是否需要同步复赛帖、演示脚本或截图。

以下改动不进入迭代池：

- 只调整代码结构、玩家与评委均无感知，且不降低明确风险；
- 没有基线证据的“感觉更好”；
- 为增加功能数量而扩大演示失败面；
- 无测试、无截图或无法复现的完成声明。

## 五、每轮固定验证顺序

1. lint 与单元测试；
2. build；
3. validate-story、simulate-paths、validate-effects；
4. 与改动直接相关的 Playwright 路径；
5. 375×812 与 1920×1080 关键帧截图；
6. Git diff 审查；
7. 复赛帖与实际功能一致性复核。

验证证据不完整时，任务保持进行中，不以“代码已写完”作为完成标准。
